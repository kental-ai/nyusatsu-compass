## ちば実装の要点（pipeline/fetch_chiba.mjs）

- 一覧に法人番号が載る=GEPSと同じキーで名寄せ可能（充足率実測94.7%。欠損はJV等）
- 700件制限は「開札日範囲を total≤500 になるまで二分割→表示上限500で1発取得」で回避（ページング不要）
- 実測: 千葉県+千葉市+船橋市の2025年度 = 5,936件を39リクエストで取得
- 収録: 2021年度〜（令和3年度〜）。KikanNO空=全機関横断でき、機関名は一覧のグループ見出しから取得
- GEPS収録企業との重なり196社 → 企業ページに「国+自治体」の実績を統合表示できる

## 全量ロールアウトの設計課題（次の実装）

Netlifyは毎ビルドでデータを持ち越さないため、自治体データ（バックフィル1,000リクエスト級）を
毎ビルド再取得するのは不可。**方式: データスナップショットをリポジトリにコミットする**

1. バックフィル（ローカル1回）: 全機関×2021〜2026年度 → local_awards
2. スナップショット出力: data/snapshots/chiba.csv.gz 等をgit管理（数MB想定）
3. 日次増分: GitHub Actionが当年度・直近窓だけ再取得→スナップショット更新をコミット→Netlifyビルドが読む
4. site/build.mjs: local_awardsを企業ページ（国+自治体の統合実績）・相場・地域ページに接続

## SuperCALS横展開の偵察結果（2026-08-16）

- **即戦力（3手プロトコル+法人番号を実機確認）**: 静岡県（ppi.cals-shiz.jp・2024年度〜・9列構成=「入札方法」列が挟まる）→ 実装済み
- **要調整**: 兵庫（プロトコル成立・機関番号の特定が課題）/ 福井（新スキーマ: NyusatuHousiki系）/
  新潟（フロー相違）/ 愛知・鹿児島・札幌市（機関番号必須の多機関型）/
  富士通ASP共同ホスト ep-bis.supercals.jp（三重・石川・鳥取等が相乗り。機関単位で取得可能とみられる）
- 知見: KikanNOは「都道府県コード2桁+00000」型。一覧の列構成は8列（ちば）と9列（静岡）の2系統 → 列数で自動判別
- 秋田の保持期間は2021年度〜（約3〜5年）。ちばは実質1年強。**保持期間はシステムごとにバラバラで、
  いずれも「取り続けた者だけが持てる」構造は共通**
