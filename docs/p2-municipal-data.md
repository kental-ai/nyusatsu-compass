## 全量ロールアウトの設計課題（次の実装）

Netlifyは毎ビルドでデータを持ち越さないため、自治体データ（バックフィル1,000リクエスト級）を
毎ビルド再取得するのは不可。**方式: データスナップショットをリポジトリにコミットする**

1. バックフィル（ローカル1回）: 全機関×2021〜2026年度 → local_awards
2. スナップショット出力: data/snapshots/chiba.csv.gz 等をgit管理（数MB想定）
3. 日次増分: GitHub Actionが当年度・直近窓だけ再取得→スナップショット更新をコミット→Netlifyビルドが読む
4. site/build.mjs: local_awardsを企業ページ（国+自治体の統合実績）・相場・地域ページに接続

### 解いた3つの問題

**1. 列数ヒューリスティックの誤判定（潜在バグ）**
旧実装は「9列なら静岡型（入札方法列が中間に挟まる）」と決め打っていたが、石川・沖縄は
9列でも余分な列が末尾の「更新日」で、落札者・金額の位置が1つずれる。
→ 一覧のヘッダー行（`No|開札…|…|落札者名|落札決定金額|…`）から列位置を引くように変更。
ヘッダーを出さないインスタンス（宮崎）は従来のヒューリスティックにフォールバック。
既存3県で回帰確認済み（千葉2026年度を再取得して新規37件＝直近3日分のみ）。

**2. 愛媛の「列ズレ」の正体と本番投入**
前回（08-23）保留した列ズレは新パーサでは0件。あわせて別の実害を発見:
**愛媛は一覧の機関見出しが団体名を含まず部局名から始まる**（例「令和8年度 総務部 契約課」）ため、
松山市以下11市9町の案件がすべて「愛媛県」に寄っていた。
→ 案件名の先頭にある調達案件番号の上5桁＝JIS X 0402 の団体コードから発注機関を復元。
出現した20コードが愛媛県の11市9町とちょうど一致し、見出しに団体名が出る4町
（砥部・伊方・松野・鬼北）で照合、案件名中の地名（神戸小＝西条市、寒川小＝四国中央市 等）とも整合。
案件番号は案件名から除去した。

**3. 栃木の落札者名の「…」**
栃木は落札者名が全角空白で固定長26字にパディングされ、末尾に表示用の「…」が付く（77%の行）。
実データを測ると「…」付きは必ずパディング後26字・本体は最長23字で、切り詰めではなく表示マーカー。
→ 末尾の空白＋「…」を除去。他県にも少数あるため共通処理にした。

### SuperCALS系との決定的な違い: 落札者名が一覧に無い
