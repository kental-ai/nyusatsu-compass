# リポジトリ肥大の解消（2026-09-06）

## 問題
毎日のスナップショット更新（自治体12MB・公告アーカイブ30MB・GEPS13MB）を全てgitコミットしていたため、
過去の巨大blobが履歴に積み上がり、.git が **361MB**（GitHub上 216MB）に肥大。
Netlifyは毎ビルドでクローンするため、放置するとビルド時間と転送量が悪化し続ける構造だった。

## 対策1: 構造（再発防止）— 公告アーカイブの年別分割
`pipeline/archive_notices.mjs` の export/import を年別ファイル方式に変更。
- `notices_archive_<過去年>.csv.gz`: 一度書いたら**凍結**（存在すれば再書き込みしない）
- `notices_archive.csv.gz`: 現行年＋日付不明分のみ（毎日更新される唯一のファイル）
- import は `notices_archive*.csv.gz` を全て読み、ヘッダ行を除いて連結（500,148行の取込を実測確認）
→ **毎日のgit差分が 30MB → 6MB に**。年が変わるたび自動で凍結ファイルが増える

## 対策2: 過去履歴の圧縮（一度きり）
`git filter-repo --path data/snapshots --invert-paths` で、全履歴からスナップショットのblobを除去し、
現行のスナップショット6ファイルを新規コミットで再収載 → force-push。
※filter-repo実行とforce-pushはセーフガードによりオーナーが手動実行

## 結果
| 指標 | 前 | 後 |
|---|---|---|
| .git | 361MB | 583KB（+スナップショット実体55MB） |
| クリーンクローン | （数分） | **4.9秒 / 55MB** |
| 毎日のコミット差分 | 約42MB | 約18MB（うちアーカイブ6MB） |

- バックアップ: `scratchpad/nc-backup.git`（旧履歴のミラー・361MB）。セッション終了で消えるため、
  旧履歴が必要なら別途保存すること（実運用上は不要）
- Git LFSは不採用: GitHub LFSの無料帯域は月1GBで、Netlifyの毎日クローンで即超過し課金が発生する構造のため

## 次に効く一手（未実施）
